
# CLAUDE.md — Persistent context for Claude Code sessions

## 1. Project Overview

A reusable **Windows Python project scaffold** that enables zero-prerequisite deployment:
no system Python required on target machines. A single `launch.bat` orchestrates
portable Python unpacking, venv creation, editable package install, and app launch.

All user runtime data (venv, config, logs, data) is stored under
`%LOCALAPPDATA%\<APP_AUTHOR>\<APP_NAME>\` via `platformdirs` — fully separated
from the read-only shared-drive source tree. Safe for multi-user network deployments.


## User Guide

To use this scaffold - modify the following files:
1. Only 2 files require modification:  
`tools\.env.default`: APP_NAME, APP_AUTHOR, ENTRY_POINT, PYTHON_ZIP_NAME  
`pyproject.toml`:name, description, dependencies, [project.scripts], [tool.setuptools.packages.find] include

2. Rename/replace the package folder:  
Rename `src\my_package\` → `src\your_package_name\`  
Update `__init__.py`: change `__version__` if needed  
Put your app logic in `__main__.py` inside main()


3. tools\.env.default — the master config:  
```
APP_AUTHOR=YourOrg          # → %LOCALAPPDATA%\YourOrg\  
APP_NAME=YourAppName        # → %LOCALAPPDATA%\YourOrg\YourAppName\  
ENTRY_POINT=src/your_package/__main__.py  
PYTHON_ZIP_NAME=python-3.12.0-embed-amd64.zip
```

4. pyproject.toml — adapt these blocks only:  
```
[project]
name            = "your-package"
description     = "What it does"
dependencies    = ["requests>=2.31.0"]   # add your deps

[project.scripts]
"your-package" = "your_package.__main__:main"

[tool.setuptools.packages.find]
where   = ["src"]
include = ["your_package*"]             # match your folder name
```

5. Add portable Python zip:  
Download embeddable zip from python.org (Windows x86-64)  
Drop it in the project root — filename must match PYTHON_ZIP_NAME  


6. Do NOT touch:  
Anything inside tools\ (bootstrap.py, env.py, run.py, *.bat)  
tools\boot\ (committed boot interpreter)  
launch.bat, virtualenv.bat  


7. First run after setup:  
launch.bat

Everything else (venv creation, pip install, dir creation) is automatic.

## 3. Architecture Overview

```text
project-root/                        # Shared drive — read-only at runtime
├── launch.bat                       # Primary entry point: boot → setup → run
├── virtualenv.bat                   # Opens pre-activated developer shell
├── pyproject.toml                   # Build config + declared dependencies
└── tools/
    ├── .env.default                 # SINGLE SOURCE OF TRUTH — committed config
    ├── bootstrap.py                 # Full setup orchestrator (run by boot Python)
    ├── env.py                       # All paths resolved here — imported by py scripts
    ├── run.py                       # Launches app via venv Python
    ├── load_env.bat                 # Reads AppData\.env into caller environment
    ├── bundle.bat                   # Runs bundle_generator.py via venv
    ├── virtualenv_banner.bat        # Dev shell welcome message — no SETLOCAL
    ├── .shell_init.bat              # Generated at runtime — gitignored
    └── boot/                        # Minimal committed Python interpreter
        └── python.exe               # Used only to run bootstrap.py

%LOCALAPPDATA%\<APP_AUTHOR>\
├── python\                          # PORTABLE_DIR — shared across all org apps
└── <APP_NAME>\
    ├── .env                         # Generated by bootstrap — never edit manually
    ├── .venv\                       # Venv bound to portable Python
    ├── config\                      # User preferences
    ├── data\                        # Local databases / caches
    └── logs\                        # Rotating log files
```

**Module interaction:** `launch.bat` reads `tools\.env.default` → derives paths →
calls `bootstrap.py` (which imports `tools\env.py`) → calls `tools\run.py` →
executes `src\my_package\__main__.py`.

## 4. Key Workflows

### First-Time Setup (`launch.bat`)
1. Read `tools\.env.default` → load `APP_NAME`, `APP_AUTHOR`
2. Derive `VENV_PYTHON` path from `%LOCALAPPDATA%`
3. `VENV_PYTHON` missing → invoke `tools\boot\python.exe tools\bootstrap.py`
4. `bootstrap.py` steps: `write_env_file()` → unzip portable Python → create venv
   → `ensurepip` → upgrade pip/setuptools → `pip install -e .` → optional Playwright
   → `platformdirs` mkdir (config, data, logs)
5. Re-derive `VENV_PYTHON` → launch `tools\run.py`

### Subsequent Runs
`launch.bat` → `VENV_PYTHON` exists → `venv Python tools\run.py` → app (all setup skipped)

### Developer Shell (`virtualenv.bat`)
1. Read `.env.default` → derive `_ENV_FILE`; if missing → run bootstrap
2. `CALL tools\load_env.bat` → inject all AppData paths into caller env
3. Write `tools\.shell_init.bat` with baked absolute paths
4. `start cmd /K .shell_init.bat` → activates venv, `cd` project root, shows banner

## 5. Coding Conventions

- **Src layout:** all packages under `src/`; folder must contain `__init__.py`
- **Entry point:** `__main__.py` with `main()` function + `if __name__ == "__main__"` guard
- **Type hints:** Python 3.10+ union syntax (`Path | None`); return types annotated
- **Path construction:** always `pathlib.Path`; chain `.mkdir(parents=True, exist_ok=True)` before writing
- **Encoding:** always explicit `encoding="utf-8"` on `open()`, `.write_text()`, `.read_text()`
- **pip invocation:** always `python -m pip` — never `pip.exe` directly
- **Subprocess:** `subprocess.run(cmd_list)` — list form, never shell string
- **Logging prefix convention:** `[INFO]`, `[SETUP]`, `[ERROR]` prefixes in print output (bootstrap/run)
- **Batch scripts:** `SETLOCAL ENABLEEXTENSIONS ENABLEDELAYEDEXPANSION` in entry `.bat` files; `!VAR!` inside those blocks
- **`load_env.bat` / `virtualenv_banner.bat`:** NO `SETLOCAL/ENDLOCAL` — variables must propagate to caller
- **Config constants:** never hardcode `APP_NAME`, `APP_AUTHOR`, `ENTRY_POINT`, `PYTHON_ZIP_NAME` — always read from `tools\.env.default` via `env.py` or bat parsing

## 7. Rules & Prohibitions

- NEVER hardcode `APP_NAME`, `APP_AUTHOR`, `ENTRY_POINT`, `PYTHON_ZIP_NAME` — read from `tools\.env.default`
- NEVER hardcode directory paths — always resolve via `env.py` + `platformdirs`
- NEVER write config, logs, or data into the project/src directory at runtime
- NEVER copy or move a venv — always generate it in-place via `portable_python -m venv`
- NEVER open files without `encoding="utf-8"`
- NEVER call `.mkdir()` without `exist_ok=True`
- NEVER call `pip.exe` directly — always `python -m pip`
- NEVER wrap `load_env.bat` or `virtualenv_banner.bat` in `SETLOCAL/ENDLOCAL`
- NEVER use `%VAR%` inside `ENABLEDELAYEDEXPANSION` blocks — use `!VAR!`
- NEVER edit `%LOCALAPPDATA%\..\.env` (generated file) — edit `tools\.env.default`
- NEVER commit `.env`, `.shell_init.bat`, `.venv/`, `python/`, `*.zip`, `*.egg-info/`
- NEVER commit `tools\boot\` to gitignore — it must be tracked
- NEVER remove the `if __name__ == "__main__"` guard from `__main__.py`
- NEVER create `setup.bat` or `setup_and_run.bat` — replaced by `launch.bat` + `bootstrap.py`
- NEVER use `setup.py` — `pyproject.toml` only

## 8. Verification Instructions

1. Delete `%LOCALAPPDATA%\<APP_AUTHOR>\<APP_NAME>\` to simulate fresh user
2. Run `launch.bat` — confirm no `[ERROR]` lines; setup runs end-to-end
3. Confirm `%LOCALAPPDATA%\<APP_AUTHOR>\<APP_NAME>\.env` was generated
4. Confirm `%LOCALAPPDATA%\<APP_AUTHOR>\python\python.exe` exists
5. Confirm `%LOCALAPPDATA%\<APP_AUTHOR>\<APP_NAME>\.venv\Scripts\python.exe` exists
6. Confirm app prints expected output and exits cleanly
7. Run `launch.bat` again — confirm all setup steps are skipped
8. Run `virtualenv.bat` — confirm dev shell opens; `(.venv)` prefix on prompt
9. Inside dev shell: `pip list` — confirm all deps present; `pip install -e .` — confirm editable install
10. Run `git status` — confirm `.env`, `.shell_init.bat`, `.venv/` are not tracked
11. Confirm no runtime paths are hardcoded — all resolve through `env.py`
